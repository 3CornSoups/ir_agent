# ir_agent 优化方案 v2：保真优先的双目标闭环

> 目标读者：用 Cursor **Goal 模式**执行本方案的模型。
> 执行纪律：**一次只改一个受控变量**，每个 Task 跑完 gate 才能进下一个。
> 文档定位：这是**执行规格**，不是设计随笔。每个 Task 都给了「交付文件 / 验收命令 / 通过标准 / 回滚条件」。

---

## 0. 一页结论

### 0.1 现状

管线本身已经跑通且不弱：五模式（t2va / i2va / fl2va / l2va / r2va）、感知 → 双路由 → 扩写 → 补细节 → 格式化 → 规则校验，eval100 上 18 维 overall_mean = **4.43 / 5**，enhance 零失败。

### 0.2 但这个 4.43 分**不能用来做决策**

| 问题 | 证据 |
| --- | --- |
| **测的不是要测的东西** | eval100 是 100 条**纯 t2va**，`d12 参考图/条件控制`全部为 `null`。而用户最核心的诉求「严格参考短意图 / 参考图 / 参考视频」，恰好**完全没有被测量** |
| **分数被压在天花板** | 18 维均分区间 4.07–4.76，跨度只有 0.69。任何真实改动带来的信号都会被淹没在裁判噪声里 |
| **裁判没校准** | 无 anchor 样例、无金标注集、无自一致性检验、无与人工/强模型的相关性验证。`temperature=0.1` 只能保证「稳定地错」 |
| **保真度只有自由文本标签** | `invented_assets`(7) / `invented_text`(5) / `identity_drift`(4) 是裁判随口生成的 tag，**不可复现、不可回归、不能设 gate** |
| **没有回归防护** | 一轮迭代同时改了 8 个维度的 prompt（见 `docs/优化与评估闭环.md`），改完只回归了 2 条低分 case。无法归因，也无法证明没有把别处改坏 |

一句话：**尺子不准，而且量错了地方。** 在修好度量之前做的任何 prompt 优化，都是在噪声上做梯度下降。

### 0.3 本方案的主张

这个系统的本质是一个**双目标问题**，而当前的单一 `overall` 均分把两个目标混成了一个数，导致「用保真度换丰富度」这种最危险的退化**在指标上看不出来**（写得更华丽 → 视觉质量/摄影语言分↑ → overall↑，但发明了用户没要的素材）。

因此本方案把目标拆成两个，且**不做加权求和**：

- **保真度 $F$（Fidelity）— 硬约束 gate。** 严格遵循短意图、严格遵循参考图/视频。不达标即判 case 失败，丰富度再高也不看。
- **丰富度 $E$（Enrichment）— 软目标。** 在 $F$ 达标的前提下最大化。

$$
\max E \quad \text{s.t.} \quad F \ge F_{\text{gate}}
$$

以及一个**北极星指标**回答「是否超越官方」：

- **盲测胜率 $W$**：同一批意图，本地 agent 稿 vs 官方 H3-Context-IR 稿，随机顺序、不告知来源，裁判做 pairwise 判优。
