# ir_agent 优化方案 v2：保真优先的双目标闭环

> 目标读者：用 Cursor **Goal 模式**执行本方案的模型。
> 执行纪律：**一次只改一个受控变量**，每个 Task 跑完 gate 才能进下一个。
> 文档定位：这是**执行规格**，不是设计随笔。每个 Task 都给了「交付文件 / 验收命令 / 通过标准 / 回滚条件」。

## 0. 一页结论

### 0.1 现状

管线本身已经跑通且不弱：五模式（t2va / i2va / fl2va / l2va / r2va）、感知 → 双路由 → 扩写 → 补细节 → 格式化 → 规则校验，eval100 上 18 维 overall_mean = **4.43 / 5**，enhance 零失败。

### 0.2 但这个 4.43 分**不能用来做决策**

| 问题 | 证据 |
| --- | --- |
| **测的不是要测的东西** | eval100 是 100 条**纯 t2va**，`d12 参考图/条件控制`全部为 `null`。而用户最核心的诉求「严格参考短意图 / 参考图 / 参考视频」，恰好**完全没有被测量** |
| **分数被压在天花板** | 18 维均分区间 4.07–4.76，跨度只有 0.69。任何真实改动带来的信号都会被淹没在裁判噪声里 |
| **裁判没校准** | 无 anchor 样例、无金标注集、无自一致性检验、无与人工/强模型的相关性验证。`temperature=0.1` 只能保证「稳定地错」 |
| **保真度只有自由文本标签** | `invented_assets`(7) / `invented_text`(5) / `identity_drift`(4) 是裁判随口生成的 tag，**不可复现、不可回归、不能设 gate** |
| **没有回归防护** | 一轮迭代同时改了 8 个维度的 prompt（见 `docs/优化与评估闭环.md`），改完只回归了 2 条低分 case。无法归因，也无法证明没有把别处改坏 |

一句话：**尺子不准，而且量错了地方。** 在修好度量之前做的任何 prompt 优化，都是在噪声上做梯度下降。

### 0.3 本方案的主张

这个系统的本质是一个**双目标问题**，而当前的单一 `overall` 均分把两个目标混成了一个数，导致「用保真度换丰富度」这种最危险的退化**在指标上看不出来**（写得更华丽 → 视觉质量/摄影语言分↑ → overall↑，但发明了用户没要的素材）。

因此本方案把目标拆成两个，且**不做加权求和**：

- **保真度 $F$（Fidelity）— 硬约束 gate。** 严格遵循短意图、严格遵循参考图/视频。不达标即判 case 失败，丰富度再高也不看。
- **丰富度 $E$（Enrichment）— 软目标。** 在 $F$ 达标的前提下最大化。

$$
\max E \quad \text{s.t.} \quad F \ge F_{\text{gate}}
$$

以及一个**北极星指标**回答「是否超越官方」：

- **盲测胜率 $W$**：同一批意图，本地 agent 稿 vs 官方 H3-Context-IR 稿，随机顺序、不告知来源，裁判做 pairwise 判优。

### 0.4 交付标准（方案完成的定义）

| 指标 | 当前 | 交付门槛 |
| --- | --- | --- |
| $F$ 保真通过率 · t2va 基线集 S1 | 未测量 | **≥ 98%** |
| $F$ 保真通过率 · 参考模式集 S2 | 未测量 | **≥ 95%** |
| $F$ 保真通过率 · 对抗集 S3 | 未测量 | **≥ 90%** |
| 未请求素材发明率 `invention_rate` | 未测量（tag 计数 16/100） | **≤ 3%** |
| 对白/屏上文字逐字保真 | 未测量 | **100%**（零容忍） |
| $E$ 丰富度中位数 | 未测量 | **≥ 0.75**（0–1 归一） |
| $W$ 盲测胜率 vs 官方 Context-IR | 未测量 | **≥ 55%**，且 $F$ 不低于官方 |
| 裁判校准 Spearman $\rho$ vs 金标 | 未测量 | **≥ 0.70** |

| 全量回归无退化 | 无机制 | 任一集合 $F$ 通过率下降 **> 1pt** 即回滚 |

## 2. 五个根因诊断

执行者要理解「为什么这么改」，否则会改歪。

### R1 — 用户意图从来没有被结构化过

管线全程是**散文到散文**：短意图 →（散文）扩写 →（散文）补细节 →（字段化散文）格式化。中间没有任何一个环节把「用户到底要什么」变成机器可校验的形式。

后果：
- 「停球→转身→射门」被压成「射门瞬间」，**没有任何一步能发现动作链丢了**（c078）
- 「禁止人脸入镜」这类否定约束，只能指望三层 LLM 都记得住
- 保真度只能靠裁判事后主观判断，无法在管线内 gate

**这是 1 号根因。** 后面所有的保真能力都建立在修好它之上。

### R2 — 「丰富」和「发明」没有被区分

现在的 prompt 里既写着「要详尽、350–450 词」，又写着「ANTI-INVENTION 禁止发明」，这两条对 LLM 来说是直接冲突的指令，模型只能猜。

正确的切分是三分法：

| 类别 | 定义 | 处置 |
| --- | --- | --- |
| **Anchored 锚定细节** | 可直接追溯到短意图或 inventory | 必须保留，等精度 |
| **Inferred 推断细节** | 从锚定细节合理推导，不引入新的显著实体（光的方向、材质反光、脚步声） | **鼓励**，这就是「丰富」 |
| **Invented 发明** | ①与意图/inventory 冲突；②引入未请求的**显著**实体（屏上文字、人脸、logo、台词、品牌、新场景） | **禁止** |

「丰富」= 最大化 Inferred。「发明」= 引入 Invented。当前 prompt 从没把这三者讲清楚，`invented_assets` 是最高频 issue_tag 就不奇怪。

### R3 — 裁判是未校准的单点

- 无 anchor：rubric 只有一句中文描述，模型对「4 分和 5 分的边界」全靠自己想
- 无金标：没人验证过裁判打的分对不对
- 单次采样：`temperature=0.1` 单次，方差未知
- 同源污染风险：裁判 prompt 里写的禁止项（译对白、画幅泄漏）和增强 prompt 里写的是同一套话术，**裁判在检查自己被告知要检查的东西**，对未预期的失败模式是盲的

### R4 — 路由是硬编码单点，且没有标注集

- 风格 skill：阈值 `0.8` 拍脑袋定的，没有 PR 曲线支撑
- T8 机制：关键词 ≥2 命中就短路 LLM，109 条机制的 triggers 里塞了拆分后的中文短语，**误命中概率很高**
- c085「手绘速写」被 `handdrawn-live` 误路由改成实拍融合，修复方式是「收紧触发词」—— 这是打地鼠，不是修根因
- **用户显式指定的风格没有最高优先级**：用户说「纯手绘」，skill overlay 说「实拍融合」，两者冲突时没有仲裁规则

### R5 — verify 只管结构，不管语义

`src/verify.py` 583 行全是结构规则：字段骨架、时间戳单调、标签编号、`<d>` 语言标记、画幅残留。README 自己承认：

> 质量校验（`src/verify.py`）规则层免费：……**不覆盖视觉语义一致性**

也就是说，管线里**没有任何一道闸门**能拦住「衣服丢了」「动作链断了」「发明了字幕」。

### 3.1 Intent Contract Schema（核心数据结构）

这是整个方案的中枢，必须先定死。

```python
# src/contract.py
@dataclass
class IntentContract:
    """用户意图契约：把短意图 + 参考素材解析成机器可校验的结构。

    这是保真度的唯一事实来源（single source of truth）。
    下游每个节点都读它，最终 verify 阶段拿它逐项 diff 最终 prompt。
    """

    # ---- 硬约束：违反即 case 失败 ----
    must_elements: list[str]        # 必须出现的主体/物体/场景，如 ["橘猫", "窗台", "阳光"]
    forbidden: list[str]            # 否定约束原文，如 ["不得切镜", "禁止人脸入镜", "不要配乐"]
    dialogue: list[DialogueLine]    # 对白/旁白：{text 原文, language, speaker}，逐字不可改
    onscreen_text: list[str]        # 屏上文字/字幕/口号原文，逐字不可改
    shot_constraint: ShotConstraint # {single_shot: bool, max_shots: int|None}
    duration_sec: float             # 4–15

    # ---- 顺序约束 ----
    action_chain: list[str]         # 有序动作链，如 ["停球", "转身", "射门"]；无序则空

    # ---- 风格仲裁 ----
    explicit_style: str | None      # 用户显式指定的风格，如 "纯手绘速写"。非空时 override skill overlay
    explicit_negatives: list[str]   # 用户显式排除的风格，如 ["不要实拍"]

    # ---- 参考素材（perceive 之后回填） ----
    reference_attrs: list[RefAttr]  # {ref_tag: "<Picture 1>", attr: "红色连帽衫", kind: identity|scene|motion|style}
    reference_roles: dict[str, str] # {"<Picture 1>": "face lock", "<Video 1>": "motion reference"}

    # ---- 元信息 ----
    intent_raw: str
    mode: str
    ambiguities: list[str]          # 解析器识别到的歧义，只记录不猜（如「既要单镜头又要三段」）
```

**设计约束（执行者必须遵守）**：

1. `parse_intent` 节点**只做抽取，禁止推断和补全**。用户没说的就是空，不许填默认值。温度 `0.0`。
2. `dialogue` / `onscreen_text` **必须是原文逐字**，包括标点。解析器如果改写了一个字，后面的逐字匹配就会永久性假阳性。
3. `ambiguities` 非空时不阻塞管线，但会记入 `run.json` 并在报告里标黄——这是产品侧后续做澄清交互的接口。

## 4. 度量定义（P0 的产出，必须先于任何优化）

### 4.1 保真度 $F$ — 10 项检查

`src/fidelity.py`。**确定性项**用正则/字符串匹配算，**判定项**用 LLM 但输出必须是 0/1 布尔，不许输出连续分数（连续分数不可复现）。

| ID | 检查项 | 类型 | 违规判定 | 是否 hard-fail |
| --- | --- | --- | --- | --- |
| FC1 | MUST 元素覆盖 | LLM entail | `must_elements` 中有任一项在最终 prompt 中无对应表述 | 否，算覆盖率，要求 = 1.0 |
| FC2 | MUST-NOT 违反 | LLM entail | `forbidden` 中任一项被违反 | **是** |
| FC3 | 对白逐字保真 | 确定性 | `dialogue[].text` 未逐字出现，或不在 `<d>` 内，或语言被改 | **是** |
| FC4 | 屏上文字逐字保真 | 确定性 | `onscreen_text[]` 未逐字出现或被翻译 | **是** |
| FC5 | 动作链保序 | LLM 定位 + 确定性排序 | `action_chain` 在 prompt 时间轴上的出现位置非单调 | 否，算保序率，要求 = 1.0 |
| FC6 | 参考属性保留 | LLM entail | `reference_attrs` 中 identity 类属性未等精度保留（含降覆盖） | 否，算保留率，要求 ≥ 0.90 |
| FC7 | 镜头约束 | 确定性正则 | `single_shot=True` 但出现 ≥2 个 `[Shot N]`；或超 `max_shots` | **是** |
| FC8 | 时间戳边界 | 确定性 | 时间戳超出 `duration_sec` 或非单调 | **是** |
| FC9 | 未请求显著发明 | LLM 枚举 | 出现意图与 inventory 都没有的**显著实体**（屏上字/人脸/logo/品牌/台词/新场景） | 否，算计数，要求 = 0 |
| FC10 | 画幅泄漏 | 确定性正则 | 出现 ratio/resolution/fps/canvas | **是**（已有实现，复用） |

**case 级判定**：

$$
F_{\text{pass}} = (\text{无 hard-fail}) \wedge (\text{FC1}=1) \wedge (\text{FC5}=1) \wedge (\text{FC6} \ge 0.9) \wedge (\text{FC9}=0)
$$

**集合级指标**：
- `fidelity_pass_rate` = 通过的 case 数 / 总数
- `invention_rate` = FC9 > 0 的 case 数 / 总数
- 每个 FCx 的独立违规率（用于定位）

> **关键实现要求**：FC1 / FC2 / FC6 / FC9 用的 LLM 判定，**必须逐项独立提问**（一个 must_element 一次判定），不许一次问一整包。一次问一整包会让模型偷懒漏判，且无法定位。可以批量并发，但逻辑上要独立。

### 4.2 丰富度 $E$ — 6 项，归一到 0–1

`src/enrichment.py`。

| ID | 指标 | 类型 | 计算 |
| --- | --- | --- | --- |
| EN1 | 锚定视觉细节密度 | 确定性 | 可执行视觉名词短语数 / 100 词，映射到 0–1（0.75 分位截断） |
| EN2 | 时间结构完整度 | 确定性 | 时间轴被节拍覆盖的秒数 / `duration_sec` |
| EN3 | 声音层完整度 | 确定性 | 环境声 / 动作声 / 配乐三层齐全度（含合理的 N/A） |
| EN4 | 镜头语汇具体度 | LLM 0/1 | 每个镜头运动是否同时有「类型 + 幅度 + 速度」 |
| EN5 | 密度比 | 确定性 | 本地稿词数 / 官方 gold_ir 稿词数，$[0.8, 1.2]$ 得 1.0，越界线性衰减 |
| EN6 | Inferred 细节增益 | LLM 计数 | 相对短意图新增的**合理**细节数（不含 Invented），映射 0–1 |

$$
E = \frac{1}{6}\sum_{i=1}^{6} \text{EN}_i
$$

EN5 只在有 gold_ir 对照的 case 上算，其余 case 该项按其他 5 项均值填充。

> **注意**：$E$ **只在 $F$ 通过的 case 上统计**。不通过的 case 的 $E$ 无意义（写得再多也是错的）。

### 4.3 盲测胜率 $W$ — 北极星

`scripts/blind_ab.py`。

流程：
1. 对有官方 gold_ir 稿的 case（母仓 7 + r2va 6 + 对照 3 + 特殊光影 3 = **19 条起步**，P0 扩到 40 条），取本地 agent 稿与官方稿
2. 随机打乱 A/B 位置，**不告知裁判哪个是官方**，也不告知这是在评自己的系统
3. 裁判输出：`{"winner": "A"|"B"|"tie", "reason": "...", "dims": {...}}`
4. 每对跑 **2 次，A/B 位置互换**，只有两次结论一致才计入（消除位置偏好）；不一致计 tie

$$
W = \frac{\text{win} + 0.5\cdot\text{tie}}{\text{总对数}}
$$

**同时报告**：本地 $F$ 通过率 vs 官方 $F$ 通过率。如果本地 $W > 55\%$ 但 $F$ 低于官方，说明是靠「写得花」赢的，不算数。

### 4.4 裁判校准

`scripts/calibrate_judge.py`。

1. **金标注集** `input/judge_gold.jsonl`：40 条（20 条来自 eval100 分数分布的分层采样 + 20 条来自对抗集），每条由**人工或 Claude Opus 级模型**标注 18 维分数 + 保真标签
2. **相关性**：Spearman $\rho \ge 0.70$，MAE $\le 0.6$
3. **自一致性**：随机 20 条各跑 3 次，overall 标准差 $\le 0.25$
4. **anchor 注入**：给 18 维每一维在 `prompts/judge_dimensions.txt` 里补 5 分 / 3 分 / 1 分各一个**具体片段样例**（不是描述，是真实文本片段）
5. **分布检验**：全集分数不能挤在 4–5，要求 $\sigma \ge 0.5$ 且 5 分占比 $\le 35\%$

校准不达标 → **P1 及之后的所有结论作废**。这是 P0 的 blocking task。

### 5.4 S4 路由标注集（60 条）

不跑全管线，只跑路由，秒级。

## 7. Goal 模式执行手册

### 7.1 迭代循环（每个 Task 内部）

```
1. 读 runs/latest/gate_report.md，取失败率最高的**一个**失败簇
2. 只改一个受控变量（一段 prompt / 一个阈值 / 一条规则）
3. 跑 quick gate（~25 min）
      ├─ 目标簇改善 且 无其它簇退化  →  进 4
      ├─ 目标簇改善 但 别处退化      →  回滚，改用更窄的改法
      └─ 目标簇没改善                →  回滚，换假设（不许"再加一句试试"）
4. 跑 full gate（~90 min）
5. 与 runs/baseline_v1 做 paired 对拍
      └─ 任一集合 F 通过率下降 > 1pt  →  **无条件回滚**
6. 通过 → 更新 baseline，写 docs/CHANGELOG.md（改了什么 / 指标变化 / 为什么）
```

### 7.2 变更纪律（**这是本方案最重要的一节**）

当前项目失败的最大原因是：一轮迭代同时改了 8 处 prompt，改完无法归因，只能靠重跑 2 条 case 说「修好了」。

**硬规则：**

1. **一次一变量。** 一个 commit 只改一个 prompt 的一个段落，或一个阈值，或一条规则。
2. **禁止"顺手也改一下"。** 发现别的问题就记到 `docs/BACKLOG.md`，不要在当前 commit 里动。
3. **禁止在 prompt 里堆叠新的大写口号。** 现在已经有 `INTENT SPINE LOCK` / `VISUAL IDENTITY LOCK` / `INTERACTION LOCK` / `SPATIAL LOCK` / `ON-SCREEN TEXT LOCK` / `AV SYNC` / `ANTI-INVENTION` / `INTENT FOLLOW` 八个了。再加只会稀释注意力。**优先改成结构化的 contract 字段引用**（模型对结构化输入的遵循度远高于口号）。
4. **每个 commit 必须附 quick gate 结果。** 没有数字的改动不许合入。
5. **prompt 改动必须可回滚。** 用 git，不要原地覆盖。

### 7.3 终止条件

同时满足即交付：

- [ ] `docs/BASELINE.md` 中 §0.4 全部 10 项交付标准达标
- [ ] 连续 **2 轮** full gate 全绿，且无任何集合退化
- [ ] S3 对抗集 12 类中，无任何一类通过率 < 75%（防止用整体高分掩盖某一类系统性失败）
- [ ] `pytest -q test/` 全绿
- [ ] `docs/CHANGELOG.md` 记录了每一次改动及其指标影响

### 7.4 已知陷阱（执行者会踩的坑）

| 陷阱 | 症状 | 对策 |
| --- | --- | --- |
| **指标刷分** | 为了过 FC1，在 prompt 里机械罗列 must_elements | 检查 $E$ 是否同步下降；加人工抽检 5 条 |
| **裁判漂移** | 改了 judge prompt 后所有历史分数不可比 | judge prompt 一旦在 T0.4 定版就**冻结**；必须改则全部重跑 baseline |
| **对抗集过拟合** | S3 满分但 S1/S2 退化 | full gate 必须三集合同时看；S3 单集合达标不算数 |

| **LLM 判定不可复现** | 同一份 prompt 两次跑出不同 $F$ | FC 判定项温度 0.0，输出限定 0/1；T0.2 里加「同输入跑 3 次结果一致」的单测 |
